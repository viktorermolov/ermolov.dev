## Source-verified lifecycle and metadata

Read actual `lib/store.js`, `popup.js`, `options.js`, `options.html`, `content.js`, manifest and export/diagnostics code at the exact source head above, rather than relying only on the PR narrative.

- `lib/store.js:446–476` (`resumeCapture`): both popup and Options call this function. Snapshot capture state, read clipboard outside the shared UI lock, recheck paused/revision, persist baseline, then write `paused:false`. UI read/storage failures are reported; changed-state attempts require retry. Resume reads the clipboard even when the automatic popup-import setting is off; the version-scoped clipboardRead-purpose disclosure must state this. Ordinary tested failures do not silently enable import. Ambiguous writes and total storage unavailability prevent absolute persistence claims.
- `meta:capture = {revision, baselineRevision, resumeHash}`. The first two fields are revision counters; `resumeHash` is the existing non-cryptographic `hashText` of normalized/truncated text (text length plus FNV-1a hash), or null for empty content. The metadata contain no raw paused clipboard text. A processed permitted page copy or saved-clip copy-back writes a boolean `meta:copy:<baselineRevision>` marker. These values are local and excluded from clip exports and diagnostics (aggregate storage-byte counts can still reflect them).
- `syncClipboard`, lines 480–503, checks fresh settings/revision around its read. The unchanged baseline survives closure/restart, with **no time-based expiry or timer that later imports it**. Different/empty normalized clipboard content observed by enabled popup import, or an observed current-revision permitted-copy marker, ends suppression. The popup import check clears `resumeHash` and tries to remove the corresponding boolean marker.
- The distinction between behavior and physical deletion matters: a permitted copy makes the baseline logically inactive; the stored hash can remain until the next enabled popup import check or a later Resume replaces it. Revision counters remain; obsolete boolean cleanup is best effort, so inert older keys may remain without time-based expiry. Uninstall removes extension storage. Do not promise immediate or timed deletion.
- `capturePage`, lines 507–516, records a permitted page event including same-text recopy; `touchClip`, lines 633–646, records saved-clip copy-back. These can end the baseline. An identical external-app recopy has no observable event: let a normal popup observe different/empty clipboard content first, then recopy. Different external-app content still imports automatically.
- `content.js` starts state observation during trusted copy/cut dispatch and rechecks before deferred writes. Page origins do not share the UI lock. Clipboard reads, copying, writes and toggles are not atomic. This is not an absolute guarantee for all text ever copied during a pause.
- The current clipboard has no origin information. `popup.js:547–560` avoids direct Incognito import, and `content.js` excludes Incognito page events; neither prevents leftover Incognito/password-manager text from entering a normal popup. The existing disable option remains.

## Prepared wording and version boundary

All pause/Resume claims, including the complete product FAQ answer and privacy storage bullet's active-capture condition, are explicitly scoped to 1.1.4. The earlier 1.1.3 cached check is not evidence of race-safe behavior. Preliminary review's version-boundary corrections were held locally and are bundled with this source-grounded update.

Exact product lifecycle wording:

> Starting with Clipstay 1.1.4, Resume saves a local fingerprint of the current clipboard before enabling capture. Popup import skips that unchanged text across popup closure and browser restart. It stops skipping it after the popup observes different or empty clipboard content, or Clipstay processes a new permitted page copy or saved-clip copy-back. This concerns the text read at Resume, not everything copied while capture was paused.

The FAQ also explains reported errors, no timer, atomicity limits and the identical external-recopy workaround. The privacy counterpart describes the two revision counters, hash/text length, boolean copy markers, no timed expiry and deferred/best-effort physical cleanup; it does not call these simply temporary metadata.
